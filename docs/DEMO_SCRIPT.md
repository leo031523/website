# 操作示範影片腳本（60～90 秒）

給實際錄影用的分鏡腳本：每個段落列出「畫面要做什麼」與「口白重點」，照順序錄，不用照著唸逐字稿，抓重點講就好。整支影片建議控制在 75 秒上下，寧可少講一點也不要趕。

錄影前先確認：本機用 `docker compose up -d` 把整站跑起來、瀏覽器視窗清乾淨（沒有其他分頁/書籤列干擾）、深色模式先切回預設（除非你想特別展示深色模式）。

---

## 1. 開場（0:00–0:08）

**畫面**：首頁。

**口白**：「這是我做的個人筆記與作品集網站，前後端分離、後台 CMS、還有一個會依據網站內容回答問題的 AI 助理。」

## 2. 前台瀏覽（0:08–0:20）

**畫面**：點「閱讀文章」進文章列表 → 點進一篇文章 → 往下滑到「到底了」的提示與回首頁按鈕 → 點右上角切換深色模式。

**口白**：「文章跟作品都是伺服器端渲染，發布後透過 ISR 立即更新，不用重新部署整個網站。」

## 3. 後台 CMS（0:20–0:38）

**畫面**：點頁尾「後台」進登入頁 → 登入 → 文章管理列表 → 點「新增文章」進編輯器，秀一下 Markdown 工具列（例如點 H2、加粗）跟即時預覽 → 點「儲存草稿」。

**口白**：「後台是自己寫的 CMS，Markdown 編輯有格式工具列跟即時預覽，草稿發布分開，發布前訪客看不到。」

## 4. AI 助理（0:38–1:05，重點段落，可以放慢）

**畫面**：回到前台首頁 → 點右上角「AI 助理」開啟對話視窗 → 指出「你的訊息會傳送給 XXX 進行處理」這行揭露文字 → 輸入一個關於網站內容的問題、送出 → 等回答出現，指著回答下方的來源引用卡片 → 點一下來源卡片，展示它連到真的文章頁面。

**口白**：「AI 助理只會根據網站上真的發布過的內容回答，每個回答都附上可以點擊驗證的來源；如果網站內容不夠回答這個問題，它會直接說不知道，不會亂編答案。」

> 如果錄影當下 AI provider 還沒設定好、或额度用不了，改成展示「錯誤處理」路徑：送出問題後，指著「AI 服務目前設定有誤，請聯絡網站管理者」的訊息跟「重試」按鈕，口白改成：「就算 AI 服務本身出問題，也不會讓使用者看到系統內部錯誤或整個當掉，會顯示清楚的訊息並且可以重試。」這樣講反而更能展示錯誤處理的完整度。

## 5. 收尾（1:05–1:15）

**畫面**：回首頁，畫面停在首頁的技術棧區塊，或直接切到 GitHub repo 頁面。

**口白**：「這個專案有超過 180 個後端測試、前端 E2E 測試，每次 push 都會跑完整的 CI；程式碼跟技術決策紀錄都在 GitHub 上公開，連結在下方。」

---

## 錄製小提醒

- 滑鼠移動不要太快，觀眾的眼睛要跟得上。
- 打字部分（例如在 AI 助理輸入問題）可以先在別處打好文字再貼上，避免打字停頓拖長影片。
- 如果要配旁白，建議先錄旁白音軌、後製再對畫面，會比邊錄畫面邊講順很多。
- 影片放 README 時可以用 GitHub 支援的方式嵌入（上傳成 repo 的 asset 或連到 YouTube/其他影音平台皆可）。
